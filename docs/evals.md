# Evaluation

The golden set ([`evals/golden.json`](../evals/golden.json), `golden-v1`) has 40 questions
written from the ingested docs (expo/expo@0e8f35c56a, react/react-native-website@20927aedfe):

- 30 Expo questions across SDK 58 and SDK 57 and the unversioned guides, including
  **4 version-sensitive pairs** (8 questions): the same question asked for SDK 58, where
  the feature is documented (expo-localization RTL options, expo-clipboard
  `android.isSensitive`, expo-file-system `File.preview()`, the expo-notifications
  `largeIcon` plugin property), and for SDK 57, where it is not;
- 10 React Native questions;
- 4 unanswerable questions (3 Expo, 1 React Native) that must be refused.

Each question has expected URLs (a page, plus an anchor where the answer lives in one
section) and a short reference answer.

## Metrics (all computed by code, `src/docpilot/evals/scorers.py`)

| Metric | Definition |
|---|---|
| recall@5 | Share of answerable questions with a matching chunk in the top 5 (expected URLs are alternatives, so this is success@5). A chunk matches when it is on the expected page and, if an anchor is expected, one of its headings has that anchor. |
| MRR | Mean of 1 / rank of the first matching chunk in the top 10 (0 if none). |
| citation precision | Verified `[n]` markers / emitted markers over all answers (verifier, decision 0004). |
| refusals correct | Unanswerable questions refused + answerable questions not refused. The SDK 57 halves of the version-sensitive pairs are not scored (refusing and saying "not in SDK 57" are both right). |
| latency | p50 / p95 of end-to-end answer time (retrieval + generation + verification); retrieval time separately. |
| $ / question | Mean cost at paid rates: generation (llm-kit ledger) + query embedding + rerank. |

The LLM judge (`--judge`, faithfulness and completeness 1-5) is reported separately when run.

Configurations: `vector` (pgvector top 40), `fulltext` (Postgres `tsvector` top 40),
`hybrid` (RRF k=60 of both + exact-API boost), `hybrid_rerank` (+ Voyage
`rerank-2.5-lite`, which falls back to the RRF order without a key).

## Reading the numbers (2026-10-05)

- **Only full-text is measured on the whole golden set so far.** Gemini's free tier embeds
  at most 1,000 texts per day per project (decision 0001); the corpus has 5,031 chunks.
  The runner refuses to score a vector-based configuration on a partly embedded corpus,
  because it would silently be scored on a subset, so those rows say "not measured" until
  the daily ingestion job completes the vectors (React Native first, then SDK 58, the
  guides and SDK 57). Re-run `uv run evals --config all --answers --record` then.
- **Rerank is not measured**: no `VOYAGE_API_KEY` in this environment. `hybrid_rerank`
  equals `hybrid` until a key is set.
- **Full-text alone is already decent** (recall@5 0.86, MRR 0.69) after one tuning step
  measured on this set: `ts_rank(.., 1)` instead of `ts_rank_cd(.., 32)` (0.72 / 0.51).
  OR-ed question terms with cover-density ranking rewarded long chunks repeating "app",
  "data", "load"; log-length normalisation fixed most of it. Chosen on the golden set, so
  the number is optimistic.
- **Citation precision 0.99**: the model almost never cites a passage it was not given or
  misquotes one; the verifier removed one marker in 40 answers.
- **The 6 wrong refusals are retrieval misses, not model timidity**: in each case the right
  section was not among the 8 passages (for example "check iOS vs Android in code" retrieved
  iOS native-module pages instead of the Platform module; "prepared statements" retrieved
  other expo-sqlite sections). The model then refused as instructed instead of answering
  from memory, which is the behaviour the grounding prompt asks for. These are the
  questions where semantic retrieval should help most; the hybrid numbers will show it.
- **All 4 unanswerable questions were refused.**
- **Latency is dominated by the development machine's network** (every Neon round trip
  ~0.5 s from Pakistan; the full-text query executes in ~30 ms on the server). Expect the
  retrieval column to drop to tens of milliseconds with Vercel and Neon in one region.
- **Who answered**: Groq `gpt-oss-120b` served 9 answers and Gemini `gemini-3.5-flash-lite`
  30. The eval sends questions back to back, so Groq's 8,000 tokens-per-minute free limit
  is full most of the time and the router takes the fallback rather than waiting (the
  interactive behaviour). Interactive traffic at a few questions a minute stays on Groq.

## Reproducing

```powershell
uv run evals --recorded                              # these numbers, from the fixture (CI)
uv run evals --config all --answers --record         # live, all four configs, refresh fixture
uv run evals --sdk react-native --config all --answers --record   # one source at a time
uv run evals --config hybrid --answers --judge       # with the LLM judge
```

Each live run also stores its metrics in `docpilot.eval_runs`.
